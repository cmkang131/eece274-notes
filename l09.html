9.1설계 절차 (교재 5.1, 5.5)

설계 = 사양을 게이트 수준 구현으로 사상하는 일.

Design = 회로 specification 을 게이트 수준 구현으로 mapping 하는 것.

단계내용세부

Step 2표준 표현으로 정식화한다부울식 또는 진리표

설계 예: Logic Function Unit

사양: 데이터 입력 A, B, 제어 입력 C0, C1, C2 셋. 논리 함수 F 는 제어 입력에 따라 아래 표처럼 정해짐.

Step 1~2 (문제 이해, 정식화)
위의 표. 입력 5개(C0, C1, C2, A, B): 제어 조합 8가지 × 데이터(A, B) 조합 4가지 = 32행 진리표.

multiplexer 기반 구현. 8:1 MUX 하나면 됨(제어 입력 C 가 선택 신호, A, B 의 함수가 데이터 입력).

게이트로 구현하려면 5변수 K-map(C2, C1 별로 A, B 값에 따른 맵)으로 최소화.

9.2가산기 설계 (교재 5.6)

Half adder 와 Full adder

Half adder
S = A ⊕ B, Cout = A·B.
Full adder
세 번째 입력 C 는 이전 자리의 carry-in(Cin). S = A ⊕ B ⊕ C, Cout = MAJ(A,B,C) = AB + BC + CA. 입력 세 개 중 1이 홀수 개면 S = 1, 2개 이상이면 Cout = 1.

다비트 가산기

  • 4-bit 가산기(S[3:0] = A[3:0] + B[3:0]): 1비트 carry-in 과 두 4비트 피연산자를 더함. 결과는 4비트 Sum 과 최상위 자리에서 나오는 1비트 carry-out.
  • full adder 블록 4개로 구성하고, 앞 블록의 carry-out 이 다음 블록의 carry-in.

예 1 · +4 + +3

A = +4 = 0100₂, B = +3 = 0011₂, CI = 0. 자리마다 carry 0, Sum = 0111₂ = +7.

CO3 = 0, CO4 = 0 (CO3: MSB 로 들어가는 carry, CO4: MSB 에서 나오는 carry). Overflow = CO3 ⊕ CO4 = 0.

예 2 · +7 + +1 (overflow)

A = +7 = 0111₂, B = +1 = 0001₂, CI = 0. 아래 자리부터 carry 가 전부 올라가서 Sum = 1000₂.

4비트 2의 보수에는 +8 이 없음. 1000₂ = −8 ≠ +8. CO3 = 1, CO4 = 0, Overflow = CO3 ⊕ CO4 = 1.

  • n비트 2의 보수(n = 비트 수): N* = (−)N = 2n − N = N̄ + 1 (N̄ 는 비트 반전). 결과는 n비트만 남김(mod 2n). N = 0이면 결과도 0.
  • 4비트 표현: −8 = 1000, −7 = 1001, −6 = 1010, −5 = 1011, −4 = 1100, −3 = 1101, −2 = 1110, −1 = 1111, 0 = 0000, 1 = 0001 … 7 = 0111.

부호 바꾸기 (−x = x̄ + 1): 1101 → 비트 반전 0010 → +1 → 0011 = 3

2의 보수 덧셈·뺄셈: carry 와 overflow

A + B → 실제 값 8, 비트 결과 1000 = −8

Cn−1 = 1, Cn = 0 → overflow = Cn−1 XOR Cn = 1

signed overflow: 실제 값 8이 4비트 범위 (-8 ~ 7) 밖이므로 비트 결과 −8가 실제 값과 다르다.

unsigned로 보면 7 + 1 = 8 (CO=0 → unsigned 범위 안). signed overflow와 unsigned overflow는 별도로 판정한다.

  • Overflow 판정: C3(MSB 로 들어가는 carry)와 C4(MSB 에서 나오는 carry)가 다르면 overflow. 양수끼리 더했는데 부호 비트가 1, 또는 음수끼리 더했는데 0 이 되는 경우.

Adder / Subtractor

  • Sub = 0 이면 덧셈, Sub = 1 이면 뺄셈. 비트마다 앞에 mux(Sel)가 Bi 와 Bi′ 중 하나를 고르고, Sub 는 맨 아래 carry-in 에도 들어감.
  • A − B = A + (−B) = A + (B̄ + 1), 2의 보수 방식. B 를 반전하고 carry-in 을 1 로 두면 뺄셈. Overflow 는 마지막 두 carry 의 XOR.

9.3Ripple carry adder 의 지연

  • Ripple carry adder(RCA)는 carry 를 낮은 자리에서 높은 자리로 전파시킴. 이 전파가 critical delay이며 시스템 동작 속도를 결정.
  • 32비트 RCA 는 최상위 carry 가 32개 full adder 의 carry 경로를 순차적으로 거쳐야 해서 느리다.

RCA 식

S = CI ⊕ A ⊕ B

CO = CI(A + B) + AB

(+ 와 곱은 논리 OR, AND)

  • 단마다 carry 경로에 게이트 지연 2개가 더해짐(CO 에 누적). 4단 RCA 에서 C1 = @2, C2 = @4, C3 = @6, C4 = @8 이고 S0 는 @2 … S3 는 @7 이다 (@N 은 게이트 지연 N개 뒤).
  • 16비트 RCA 는 지연이 @32 로 비효율적. 16번째 full adder 가 첫 번째 full adder 의 carry 를 기다려야 하기 때문. 앞 단을 안 기다리고 carry-out 을 미리 알아내는 방법이 필요.

9.4Carry lookahead adder (CLA)

  • 4-bit ripple adder 에서는 Ci+1 이 Ai, Bi, Ci 의 함수. Carry lookahead 는 Ci 를 Ai, Ai−1, …, Bi, Bi−1, …, C0 로 곧바로 표현.

Carry lookahead

Ci+1 = Gi + CiPi (+ 는 논리 OR, 곱은 논리 AND)

Ci+1 = 1 인 경우: Ai 와 Bi 가 모두 1 (carry generate, Gi), 또는 Ci 가 전파될 때 (carry propagate, Pi).

Ci 를 반복 대입.

C1 = G0 + P0C0

C2 = G1 + P1C1 = G1 + P1G0 + P1P0C0

C3 = G2 + P2G1 + P2P1G0 + P2P1P0C0

C4 = G3 + P3G2 + P3P2G1 + P3P2P1G0 + P3P2P1P0C0

  • carry 식은 Pi, Gi 를 쓴 2단 논리 네트워크로 구현(Pi, Gi 생성 논리는 따로 필요). 변수가 가산기 입력과 C0 뿐이라 앞 단 carry-out 을 기다리지 않음.
  • 지연. Pi, Gi 계산이 @1, lookahead 로 Ci 계산이 @2. 그래서 Ai, Bi, C0 에서 Ci 까지 @1 + @2 = @3. Si = Pi ⊕ Ci 는 Ci 뒤에 XOR @1 이 붙어 @4. (RCA 는 S3 가 @7.)
  • Si = Ai ⊕ Bi ⊕ Ci = Pi ⊕ Ci.

Hierarchical CLA (16-bit)

  • 그룹 propagate: P3-0 = P3P2P1P0. 그룹 generate: G3-0 = G3 + G2P3 + G1P3P2 + G0P3P2P1.
  • C4 = G3 + P3G2 + P3P2G1 + P3P2P1G0 + P3P2P1P0C0 = G3-0 + C0·P3-0.
  • 16비트 가산기 = 4-bit 가산기 4개 + 4-bit Lookahead Carry Unit. 각 4-bit 가산기는 내부 carry lookahead 로 그룹 P, G 를 내보냄. 두 번째 레벨의 lookahead carry unit 이 이를 16비트로 확장(C4, C8, C12, C16).
  • 그룹 P3-0 은 AND 로 @1, 그룹 G3-0 은 OR-AND 로 @2. 첫 4-bit 블록의 S3 = P3 ⊕ C3 는 C3 = @3 에 XOR @1 을 더해 @4.
두 번째 블록
C4(두 번째 블록의 carry-in)가 @4 에 나옴. 블록 안 lookahead 로 C7 까지 @2, XOR @1 이 더해져 S7 = @4 + @2 + @1 = @7.
네 번째 블록
carry-in C12 는 @5, S15 = @5 + @2 + @1 = @8. RCA 16비트는 @32 였으니 차이가 큼.

9.5Carry select adder

  • carry 계산을 빠르게 하려고 하드웨어를 중복해서 씀.
  • 상위 자리의 합을 병렬로 계산. 한쪽은 carry-in = 0, 다른 쪽은 carry-in = 1 로 가정. 실제 carry 가 도착하면 mux 로 맞는 쪽을 고름.
  • hierarchical로 확장 가능.

9.6BCD adder

  • BCD(binary coded decimal): 10진수 0~9 를 4비트 이진수 0000~1001 로 표현. 예: 13 은 BCD 로 0001_0011.
  • 예: 5 + 8. 이진 합 1101(13)은 BCD 로는 틀림. 보정: 자릿수 합이 9 를 넘으면 6(0110₂)을 더함. 1101 + 0110 = 1_0011, 즉 0001_0011.
  • 구현: 일반 4비트 이진 가산기로 더하고, 합이 9 를 넘으면(11XX 또는 1X1X, X 는 0·1 무관. 혹은 carry-out = 1) 0110₂ 를 더하는 두 번째 가산기를 추가.
