L12. Timing Methodologies and Registers

Lecture 12

12.1Latch 와 flip-flop 복습

Latch = level sensitive, flip-flop = edge triggered.

LatchFlip-flop
동작level sensitive (transparent). clock(En)이 high 인 동안 출력이 D 를 따르고 low 이면 값을 유지edge triggered. clock edge 에서만 출력이 바뀐다 (opposite clock 의 master + slave latch)
다른 이름transparent latch, D latchmaster-slave flip-flop, D flip-flop, D register
특징면적은 더 크지만 견고하다: edge 사이의 입력 변화는 Q 에 닿지 않는다

12.2Timing methodology

Flip-flop 의 타이밍 제약

  • Setup time Tsu: clock edge 전에 data 가 안정(변화 없음)해야 하는 시간.
  • Hold time Th: clock edge 후에 data 가 안정해야 하는 시간.
  • clock → Q delay 가 지나야 F/F 출력이 안정됨.

연결된 flip-flop (shift register)

  • D flip-flop 두 개를 이어 2단 shift register 구성. 입력 In = "0101011" 이 clock 마다 한 단씩 전파됨. Tp = propagation delay.
  • 동작은 clock 한 주기에 F/F 하나씩 통과. 그럼 만족해야 할 타이밍 제약은?

Setup 과 propagation

  • Tp: F/F0 의 clock 에서 F/F0 의 출력 Q0 (= D1)까지의 delay. Tperiod: clock 주기. Tsu: setup time.

Timing constraint 1

Tp < Tperiod − Tsu

Tperiod > Delay(F/F0) + Tsu(F/F1)

  • 두 F/F 사이에 조합 논리(CL)가 있으면 전체 delay = (F/F0 의 clock → Q0 delay) + (Q0 에서 D1 까지 조합 논리 delay). 같은 제약 Tp < Tperiod − Tsu 를 이 전체 delay 에 적용.

Hold 와 propagation

  • setup 을 만족해도 이번엔 신호가 너무 빠른 게 문제. F/F0 의 출력이 너무 일찍 바뀌면 F/F1 의 hold time 이 끝나기 전에 D1 이 바뀜 (hold time violation). F/F 입력은 OK 구간에서만 바뀌어야 함.

Timing constraint 2

Tp > Th (hold time violation 회피)

Positive edge triggered 시스템 정리

Setup: Tp,max < Tperiod − Tsu

Hold: Tp,min > Th

  • setup 은 가장 느린 경로, hold 는 가장 빠른 경로의 delay 로 계산.
  • hold violation 은 clock 주파수를 낮춰도 안 없어짐. hold 제약에 Tperiod 가 없기 때문. 해결은 data 경로에 buffer 넣기, 또는 clock skew 줄이기.

비유: 자동차, 횡단보도, 아주 짧은 초록불

규칙
자동차는 초록불 한 번에 횡단보도를 딱 하나만 지남. 신호등은 거의 늘 빨강이고 순간만 초록 (= clock rising edge).
대응
횡단보도 = flip-flop, 초록불 = clock rising edge, 빨강 = Tperiod 의 나머지, 횡단보도 사이의 도로 = 논리(이동 시간 Tp), 초록불 하나에 횡단보도 하나 = clock 하나에 한 단, 정지선에서 기다림 = D 입력에 data 가 안정.
Setup violation: 차가 너무 느리다Hold violation: 차가 너무 빠르다
상황B 가 초록이 될 때 아직 도로 위에 있다. 정지선에서 Tsu 만큼 먼저 기다려야 하는데 못 맞춰 이번 초록을 놓치고 한 주기를 기다린다(data 가 한 clock 늦음). 깜빡이는 순간에 정확히 도착하면 길 가운데 서 버린다 = metastableA 를 지난 차가 같은 초록에 B 까지 간다. 초록이 Th 동안 켜져 있는데 그 안에 B 에 도착한다. 한 초록에 횡단보도 둘을 지나서 다음 단이 잘못된 data 를 받는다
해결더 짧은 도로(빠른 논리, pipelining) 또는 더 긴 빨강(느린 clock). Tp,max + Tsu < Tperiod더 긴 도로(buffer 로 delay 추가). Tp,min > Th. 더 긴 빨강(느린 clock)은 해결책이 아님

Clock skew

  • Clock skew: 같은 source 의 clock 이 위치에 따라 다른 시각에 도착하는 현상. clock B 가 늦으면 skew 는 양수.
skew 를 넣은 제약

Setup: Tp < Tperiod − Tsu + Tskew

Hold: Tp > Tskew + Th

  • 양의 skew 는 setup 에 유리. 두 번째 F/F 의 clock edge 가 늦어져 data 가 안정될 시간이 늘어남.
  • 반면 hold 에는 불리. 두 번째 F/F 의 clock edge 가 늦으니, 첫 F/F 의 새 data 가 hold time 이 끝나기 전에 도착해 버릴 수 있음.

예제: 타이밍 제약

문제

주어진 값: Tcq = 2 ns (두 F/F 모두 clock → Q delay). CL delay = 5 ns (max) / 1 ns (min). Tsu = 1 ns, Th = 1 ns. Tskew = t(clock B) − t(clock A) (양수이면 clock B 가 늦게 도착).

Q1. skew 가 없을 때 (Tskew = 0): (a) 최소 clock 주기 Tperiod 와 최대 주파수 fmax. (b) hold 제약을 만족하는가, 여유는?

Q2. clock B 가 1.5 ns 늦게 도착 (Tskew = +1.5 ns): (a) 최소 주기. (b) hold 여유.

Q3. Tskew = +2.5 ns: 어떤 주파수에서든 동작하나? 안 되면 어떻게 고치나?

풀이

경로 delay: Tp,max = Tcq + CLmax = 2 + 5 = 7 ns, Tp,min = Tcq + CLmin = 2 + 1 = 3 ns.

Q1. Setup: Tp,max + Tsu < Tperiod 이므로 Tperiod > 7 + 1 = 8 ns, fmax = 125 MHz. Hold: Tp,min > Th 에서 3 ns > 1 ns 이므로 OK, 여유 2 ns (Tperiod 는 나오지 않는다).

Q2. Setup: Tperiod > 7 + 1 − 1.5 = 6.5 ns, fmax ≈ 154 MHz (양의 skew 가 setup 에 도움). Hold: Tp,min > Tskew + Th 에서 3 ns > 2.5 ns 이므로 OK, 여유는 0.5 ns 로 줄어든다.

Q3. Hold: 3 ns > 3.5 ns ? 위반이다. 어떤 clock 주파수에서도 위반이다 (clock 을 느리게 해도 소용없다). 해결: data 경로에 0.5 ns 이상 buffer 를 넣거나 skew 를 줄인다(clock tree balancing). 예: 1 ns buffer 를 넣으면 Tp,min = 4 ns > 3.5 ns 로 OK 이고 setup 도 Tperiod > 8 + 1 − 2.5 = 6.5 ns 로 괜찮다.

정리. setup 은 가장 느린 경로 대 Tperiod (clock 을 늦추면 해결). hold 는 가장 빠른 경로 대 Th + Tskew (clock 주기가 식에 없음).

Metastability 와 synchronization failure

  • F/F 입력이 clock edge 근처(setup 과 hold 구간 안)에서 바뀌면 어떻게 되는가? F/F 이 metastable 상태에 들어갈 수 있다. Q 가 꽤 오랫동안 logic 0 도 1 도 아닌 상태다. clock 과 입력 D 를 묶어 둔 회로에서 D 와 clock 이 함께 바뀌면 Q 가 metastable 상태로 간다.

Asynchronous input

  • 비동기 입력은 F/F 입력에 아무 때나 도착해서 synchronization failure 를 일으킬 수 있음.
  • 처리: synchronizer. 비동기 입력을 쓰기 전에 시스템 clock 으로 구동하는 F/F 로 샘플링. 실패 확률은 줄지만 0 은 못 만들며, F/F 두 개를 직렬로 쓰는 게 일반적.

12.3Register (교재 6.3)

  • Register: 제어와 논리가 비슷한 F/F 의 모음. 서로 관련된 값을 저장하고, clock, reset, set 선을 공유함.
  • 예: parallel register, shift register. 4입력 register 는 F/F 4개가 IN1~IN4 를 병렬로 받아 OUT1~OUT4 를 냄.

Shift register

  • 4-bit shift register: 마지막 입력 4개의 샘플을 순서대로 보관한다. 병렬 출력은 OUT1~OUT4, 직렬 출력은 OUT4. "Quad right-shifting shift register" 는 직렬 입력을 받는다.

Serial-parallel 변환

  • shift register 는 직렬 data 와 병렬 data 를 서로 변환. Serial-in parallel-out (SIPO): 직렬로 들어와 병렬로 나감. Parallel-in serial-out (PISO): 병렬로 로드해 직렬로 내보냄.

Universal shift register

  • 한 단(N번째 cell)을 보면 다음 clock 의 새 값은 control 입력 s0, s1 과 clear 로 정해진다. 각 cell 앞에 mux 가 있고 입력은 Q[N−1] (왼쪽 cell), Q[N+1] (오른쪽 cell), Input[N] 과 자기 자신이다.
clears0s1new value
1--0
000output (hold)
001left FF 의 출력 (shift right)
010right FF 의 출력 (shift left)
011input (load)

응용: 직렬 전송

  • 병렬 data 를 보내야 한다고 하자. 목적지가 멀면 선을 여러 개 쓰는 것은 경제적이지 않다. 선 하나로 직렬 전송하는 것이 낫다. parallel-to-serial 변환으로 보내고 받는 쪽에서 serial-to-parallel 변환으로 되돌린다. 단점: 전송 data rate 가 낮다.

12.4요약

  • F/F 기반 동기 시스템의 타이밍(교재 6.2): setup Tp,max < Tperiod − Tsu (+ Tskew)는 최대 clock 주파수를 정한다. hold Tp,min > Th (+ Tskew)는 clock 주기와 무관하다.
  • 양의 clock skew (받는 F/F 의 clock 이 늦음): setup 에 유리, hold 에 불리.
  • setup/hold 구간 안에서 입력이 바뀌면 metastability 발생. 비동기 입력에는 synchronizer 필요.
  • Register (교재 6.3): parallel register, shift register(SIPO/PISO), universal shift register(hold / shift right / shift left / load).
